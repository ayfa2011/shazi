# Android feature parity checklist

## Release rule

The user has asked to wait on the final APK until the remaining implementation and checks are complete. Debug APKs may be built only as needed for emulator verification. Do not create or distribute a release APK until every required item below is implemented and checked against the website.

The Android app must remain a separate client. Keep the website, Firestore rules, Realtime Database rules, Cloud Functions, and Worker behavior unchanged unless a separately approved backend change becomes necessary. Reuse the existing Firebase project and the current two accounts.

## Android development home

The user wants future Android application changes to be made in this `android/` project as the primary development location. Website code does not update automatically; shared backend data and approved server behavior stay compatible across clients.

## Shared app shell

- [x] Two-profile picker and Firebase Email/Password sign-in.
- [x] Native app icon and launch splash.
- [ ] Match the website's colors, type, safe-area spacing, dialogs, loading states, and responsive layouts throughout.
- [ ] Main navigation for Home, Memories, Games, Post, Letters, and More; native back behavior must match each nested website flow.
- [ ] Header actions: partner presence, unread notifications and badge counts, music screen, and current-profile menu. Native dashboard has live unread count badge, chat/notification shortcuts, and a working Music screen entry; profile menu has sign-out only.
- [ ] Sign-out and app/session lifecycle behavior aligned with the website's explicit-login session model.
- [ ] Shared loading, empty, offline, permission-denied, and retry states with the website's intent and wording.
