# Our Little World — Couple Website

A mobile-first private couple website with English UI, Firebase Authentication, Cloud Firestore, Realtime Database features, memories, bucket list, questions, challenges, letters, mini games, collaborative drawing, and shared music.

## Current Firebase setup
- Firebase project: `our-little-world-e9cbb`.
- Web app configuration is in `firebase/firebase-config.js`.
- Email/Password sign-in is enabled.
- Firebase Authentication has one account for each partner. The login screen lets each person choose their name and enter the password for that Firebase account.
- Cloud Firestore is created in `nam5` (United States multi-region). Its rules allow only the two configured partner accounts to access `couples/our-little-world/**`.
- `firebase/firestore.indexes.json` defines the composite index used by typed item lists. Deploy the index and current Firestore rules from the project root with `firebase deploy --only firestore:indexes,firestore:rules` after selecting the Firebase project; wait for the index to finish building before testing lists.
- Realtime Database is ready at `https://our-little-world-e9cbb-default-rtdb.firebaseio.com/` in `us-central1`. Its rules allow only the two configured partner accounts.
- The Games page includes SOS, Memory Match, Find the Words, Emoji Quiz, and True or False. Find the Words opens as a full-screen live game with a 14×14 grid and 16 randomly selected words from a 200+ common-word bank; each new round gets a fresh set, and found words, partner presence, and scores sync through Realtime Database. Start or join a match from each game card; Realtime Database saves active turns and progress, while Cloud Firestore stores completed match results and per-game leaderboards.
- More > Special Days keeps shared birthdays, anniversaries, and celebrations with yearly or one-time dates, editable by either partner. Upcoming dates count down automatically, and the Dashboard reminds you of dates occurring within three days. Deploy `firebase/firestore.rules` with `firebase deploy --only firestore:rules` to enable shared Special Days edits and deletes for both partners.
- The header notification bell shows the partner's unread count and live updates for questions, challenge actions, drawings, memories, letters (including scheduled deliveries), posts, comments, likes, bucket-list dreams, special days, game wins, and music activity. In the notification panel, each partner can opt in to browser/system alerts while the website is open; installable-app notifications use the service worker. Deploy `firebase/firestore.rules` with `firebase deploy --only firestore:rules` to enable all notification types. True background push while the app is closed requires a push service/FCM sender and platform credentials.
- The Dashboard includes a shared days-together counter and Shazy/Kabir diary walls. Posts, likes, comments, replies, and short voice replies are saved in Cloud Firestore.
- The Dashboard uses one shared couple feed for text and photo posts. Each person can edit or delete their own posts; both can like, comment, and reply.
- The Dashboard post preview shows up to the two most recent posts from the other partner; create posts from the Post tab. Deploy `firebase/firestore.indexes.json` with `firebase deploy --only firestore:indexes` to enable the partner-only Dashboard post query.
- The Music drawer stores audio files in Telegram through the authenticated Cloudflare Worker and keeps Telegram file references in Firestore. Realtime Database coordinates playback: a transaction grants one partner exclusive control while a song is uploading or playing; playback position is synchronized, while each device controls its own volume. Playback continues when the drawer is closed or the couple navigates to another app page. Unsaved Telegram uploads are deleted after playback ends or both partners leave the website. Songs added to Saved Music remain in the shared library. Partner chat is available from the online profile photo across the site.
- Photos, videos, audio, canvas exports, profile pictures, challenge submissions, and Gallery media upload to Telegram through the authenticated Cloudflare Worker. Firestore stores text metadata and Telegram file/message references; it does not store media bytes. The Worker streams original Telegram media back to signed-in users. Firebase Storage rules deny access and no Firebase Storage SDK is used by the app.
- The floating pencil or dashboard drawing preview opens the full-screen live canvas featuring an Apple Markup / Notes style toolbar: a Pen tool (solid ink), Pencil tool (textured graphite), Marker / Highlighter tool with adjustable stroke width and opacity (with live opacity printed on the marker barrel), an Eraser, and an Apple-style rainbow Color Picker palette. The canvas engine supports smooth quadratic bezier curve smoothing on desktop and mobile, per-tool width and opacity settings, dual-buffer real-time rendering, shared undo/redo for the latest 30 strokes, clear confirmation with restore, online presence, and a History overlay ordered newest-first. Keyboard shortcuts: Cmd/Ctrl+Z to undo, Cmd/Ctrl+Shift+Z to redo, and 1-4 to switch tools. Strokes drawn while offline are stored in a per-user local outbox and sync when the device reconnects; shared clear/restore operations discard stale queued strokes. The dashboard preview shows the last shared drawing. Saved drawing exports retain the canvas aspect ratio and are forwarded to Telegram; Firestore contains only Telegram references and drawing metadata.
- The More > Profile screen shows only the signed-in partner's profile, and Firestore rules limit profile edits to that account. Display names and bios update across shared content. New profile photos are stored in Telegram and their references are saved with the profile metadata.
- Firestore rules restrict diary post edits and deletes to their author. New scheduled letter bodies are stored separately; only the author can read them before delivery, and the intended recipient gains access after delivery. Legacy scheduled letters are moved to protected storage when either partner next opens Letters.
- Today's Question seeds an original 105-question bank across seven categories into Firestore on first use, selects a stable daily question, and stores question history. Each partner's answer is in a separate protected document; Firestore rules allow reading the partner's answer only after both partners have submitted. The first time each partner opens Question History, their own legacy answers are migrated from the old shared feed into their private answer documents. Publish the updated `firebase/firestore.rules` for the answer privacy guarantee to apply in Firebase.
- Dashboard's Daily Challenge card opens the compact Challenges page. Daily Snap and water tasks remain visible there; the Give a Challenge / Punishment button opens the shared challenge hub with profile summaries, incoming and sent challenges, and history.
- Partner-created challenges can be accepted and completed; the recipient has no reject action. Creators can edit an active challenge, and its deadline countdown updates live. Daily history keeps records for 30 days and partner-created challenge history permanently.
- The app includes a service worker and install icons for installation on supported browsers. Serve it over HTTPS (GitHub Pages qualifies); Firebase-backed features still require an internet connection.
- This source currently contains the account emails used by Firebase client-side rules and profile matching. Those emails are not secrets in Firebase's security model, but they are personal information: keep the repository private or migrate the authorization checks to Firebase Authentication UIDs before making the repository public. Making the repository private does not remove data already present in Git history or deployed hosting.

## Rules files
`firebase/firestore.rules`, `firebase/database.rules.json`, and `firebase/storage.rules` are local source files. Updated Firestore restrictions must be published to Firebase to take effect. Changes to `worker/worker.js` must also be deployed to Cloudflare for Telegram upload and media proxy behavior to take effect.
